## Research Findings (Research Agent)
- `[autoload]` registration: `EventBus="*res://autoload/event_bus.gd"` — the `*` prefix (verified in Godot source, `project_settings.cpp`) is what makes the language runtime register a global constant so `EventBus.foo` resolves; without it you'd need `get_node("/root/EventBus")`. Autoloads instantiate in declaration order, all before the main scene; safe to connect to `EventBus` signals from any script's `_ready()` with no null-guards needed.
- **`process_mode = Node.PROCESS_MODE_ALWAYS` on `GameState` is mandatory**, not optional — verified live: a default-mode (`INHERIT`) autoload under a paused tree stops receiving `_input`/`_unhandled_input`, meaning `GameState` could never receive an "unpause" keypress once `PAUSED` — a real soft-lock. `EventBus` doesn't strictly need it (signals still fire while paused, verified live) but set it anyway for symmetry/future-proofing.
- `Node.ProcessMode` enum (4.7, verified against class ref): `PROCESS_MODE_INHERIT=0` (default), `PROCESS_MODE_PAUSABLE=1` (root node default), `PROCESS_MODE_WHEN_PAUSED=2`, `PROCESS_MODE_ALWAYS=3`, `PROCESS_MODE_DISABLED=4`.
- `Input.mouse_mode` enum verified correct as CLAUDE.md already has it (`MOUSE_MODE_VISIBLE`, `MOUSE_MODE_CAPTURED`, etc.). **Headless caveat:** setting `mouse_mode` silently no-ops with no window present — verified live (stayed `0`/VISIBLE after setting CAPTURED). QA must not assert on this headlessly.
- **Blocker found, verified by reproduction:** CLAUDE.md's `signal stance_swapped(new_stance_resource: StanceData)` references a `StanceData` class that doesn't exist until Step 5 — this is a genuine parse error (`Could not find type "StanceData" in the current scope`), and a broken autoload script fails **silently to `null`**, cascading into `Invalid access ... on a base object of type 'Nil'` everywhere else `EventBus` is touched. Two fixes, both verified to work: (a) ship a 2-line stub `resources/stance_data.gd` (`class_name StanceData` / `extends Resource`) now, Step 5 fills it in later; (b) type the signal param as plain `Resource` and re-narrow in Step 5. Research recommends (a) — keeps the charter's signal signature byte-identical.
- **The Step 1 `--import` then `--quit` ordering is now load-bearing, not just tidy**, under option (a): `class_name` resolution depends on `.godot/global_script_class_cache.cfg`, which only exists after `--import` has run. Skipping straight to `--quit` on a fresh clone reproduces the parse error even with correct code.
- **Exit code 0 is not sufficient to detect autoload breakage** — verified live, every failure mode above (parse error, failed autoload instantiation, Nil access) still exited 0. QA must grep output for `ERROR:`/`SCRIPT ERROR:` (already the Step 1 convention) — this becomes the *only* signal that catches autoload regressions from here on.
- Naming: CLAUDE.md's prose says `EventBus.gd`/`GameState.gd` (PascalCase filenames), but Step 1 already established snake_case filenames per the Godot style guide (case-sensitive exported filesystem). Research recommends snake_case files (`autoload/event_bus.gd`, `autoload/game_state.gd`) with PascalCase **autoload keys** (`EventBus`, `GameState` — these are the global identifiers, unrelated to filename casing), consistent with Step 1 and Godot convention.

## Design References (Elden Ring / Genshin Impact)
- CLAUDE.md's DIALOGUE/CUTSCENE spec (world keeps ticking, `get_tree().paused = false`, mouse captured) already matches the better convention — Genshin freezes only the player character during dialogue while the world keeps breathing (ambient anims, camera framing); Elden Ring's "freezes" are full authored cutscene takeovers, not a paused world. Nothing to change here.
- Since whole-tree pausing is deliberately *not* used for DIALOGUE/CUTSCENE, a narrower "is player input locked" gate is needed for those states, and Step 2 should name it once rather than let Steps 3-5 each invent their own comparison against `GameState.current_state`.
- **Recommendation adopted:** add one helper method `GameState.is_player_input_locked() -> bool` (returns `current_state != State.PLAYING`) for the Player controller (Step 4) and input buffer (Step 3) to poll each frame/input-event. Polling beats a new signal here — this is a per-frame *condition*, not a discrete *event*; signals are reserved for things like `player_died`/`parry_executed`. **No new EventBus signal added.**
- Important nuance flagged for Step 3/4 implementers: the lock must gate player action input only, not the camera (both reference games keep camera framing alive during dialogue) — and Step 3's input buffer should **drop** inputs while locked rather than queue them, to avoid a phantom buffered dodge/attack firing the instant dialogue ends.
- **Stance-swap lock:** recommendation is this stays entirely a Step 4/5 Player-controller concern (an animation-window check like Genshin's swap-cooldown or Sekiro/Elden Ring's attack-frame lock), NOT a `GameState` enum value or flag — `GameState` is a singleton and can't represent per-actor action locks, which matters once enemies (e.g. Lord Osamu, per CLAUDE.md 8.1) also have independent stance state. `GameState` only contributes the coarse `is_player_input_locked()` gate from above; `stance_swapped` still fires after the swap commits, purely as a notification signal. **No enum changes.**
- Net: zero new signals beyond the charter's existing list, zero enum changes, one new helper method on `GameState`.
